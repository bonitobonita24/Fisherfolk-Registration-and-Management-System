FRMS — Fisherfolk Registration & Management System

The digital backbone for registering, tracking, and supporting every fisherfolk, household, vessel, and aid program in the municipality — in one governed, auditable platform.

Built for the Calapan City Fisheries Management Office (FMO) — Local Government Unit deployment

3,000+ fisherfolk registered 5 core record types 18+ modules WCAG 2.2 AA compliant Multi-tenant architecture 62 barangays mapped
00

Platform Foundations

Cross-cutting capabilities every module inherits — security, identity, and accessibility are not features bolted on, they're the ground floor.

🏛️

Multi-tenant SaaS

One platform, many Local Government Units — each sees only its own data.

  • Per-municipality data isolation (tenant-scoped, L1–L6 security model)
  • Tenant-as-subdirectory routing by default
  • Optional custom-domain masking per tenant
🔐

Authentication & Roles

Every action is tied to a known, permissioned identity.

  • Username/password login (bcrypt-12 hashing)
  • "Remember me" — 30-day persistent session
  • 5 roles: super_admin, admin, encoder, viewer, bantay_dagat
  • Role-based menus and permissions throughout
🎛️

Accessibility & Theming

Designed to meet government accessibility standards, not just look good.

  • WCAG 2.2 AA — government hard gate
  • Light & dark mode, system-aware
  • Per-tenant accent color theming
  • shadcn/ui component system, fully responsive

Sign-in

Purpose: the front door — a clean, tenant-branded login gate.

  • Username-based login, bcrypt-12 password hashing
  • "Remember me" 30-day session
  • Tenant-scoped credential check (suspended tenants are blocked here)

02

Records

The core registry — the people, households, vessels, cases, and aid that FRMS exists to track.

Fisherfolk

Purpose: the master registry of municipal fisherfolk.

  • Searchable / filterable masterlist (3,000+ records, paginated)
  • Multi-step registration wizard
  • Rich profile detail — photo, signature, QR, demographics
  • 6-category classification badges
  • Registration lifecycle + "ID released" status
  • Renewal history
  • Related vessels / violations / ayuda
  • Household-membership badge (HH-####, Head/Member) linking to the household
  • Activity timeline
  • File attachments
  • "Make ToDo" quick action
  • Format-agnostic legacy-ID preservation
  • Edits route through the Edit-Request approval workflow

Household

New · 2026-07

Purpose: group fisherfolk into households (head + members) for household-level aid & reporting.

  • Explicit Household records with a designated head who is also a member
  • Auto HH-#### numbering per municipality
  • List shows head, member count, barangay, and the head's category
  • 3-step create wizard: pick head → add members → review & save
  • Detail page — add/remove members, change head, edit barangay/address/notes, delete
  • Deleting a household unlinks members — it never deletes people
  • Powers per-household ayuda distribution and household dashboard counts

Vessels

Purpose: register and track fishing vessels.

  • Vessel registration — MFVR number + specifications
  • Searchable list
  • Detail view with photos, specifications, owner (fisherfolk) link, related records
  • "Make ToDo" quick action

Violations

Purpose: log and follow fishery-law violations (Bantay Dagat).

  • File-violation form
  • Status workflow: Active → Lifted / Resolved
  • Evidence file attachments
  • Violator linked to a fisherfolk record OR entered as free text
  • Lift / resolve actions
  • "Make ToDo" for follow-ups

Ayuda

Purpose: manage government aid / relief programs for fisherfolk.

  • Aid programs with Draft → Published → Closed lifecycle
  • Beneficiary management
  • Distribution-unit toggle — per-fisherfolk OR per-household
  • Household mode records the head as beneficiary, one per household, dedup-guarded
  • Supporting file attachments
  • "Make ToDo" quick action
03

Operations

The day-to-day workflows that keep the registry accurate, actionable, and up to date.

Edit Requests

Purpose: safe, auditable edits to registry data.

  • Encoders submit an edit request
  • Admins approve or reject
  • In-app + email notifications (SMS-ready)
  • Full change tracking

ToDo — Kanban + Calendar

New · 2026-07

Purpose: a shared team task board tied to the actual records — ayuda dates, violation follow-ups, missing-data reminders.

  • Kanban view — Google-Keep-style cards across To Do / In Progress / Done columns
  • Move menu, priority accent, due-date chip with overdue flagging
  • 🔗 link back to the source record on each card
  • Calendar month-grid view with a "No Due Date" list
  • "All / Assigned to me" filter
  • "Make ToDo" button on Fisherfolk, Vessel, Violation & Ayuda pages — pre-fills a context title and links back to that record
  • Each record page lists its linked todos
  • Assignee defaults to the creator

Reports

Purpose: produce official lists & summaries.

  • 9+ report types, including a Household Masterlist
  • Filter by barangay / category
  • Excel export
  • Print-ready output

Data Import

Purpose: bring legacy & bulk data into FRMS cleanly.

  • Excel/spreadsheet import wizard — upload → preview → commit
  • Incremental import
  • Barangay alias mapping
  • Duplicate detection
  • Photo / signature import with auto-linking

ID Generator

Purpose: issue fisherfolk ID cards.

  • Template-driven ID card generation with QR
  • Batch generation
  • Visual ID-template designer (in Settings)
